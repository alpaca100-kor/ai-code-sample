# PDF → JPG 변환기 JavaScript 웹앱 제작 요청

## 1. 개발 환경

- 언어 : HTML / CSS / JavaScript
- 프레임워크 :
  - [x] Vanilla JS
  - [ ] React
  - [ ] Vue
  - [ ] 기타 :
- 파일 구성 :
  - [x] 단일 HTML 파일
  - [ ] 별도 파일
  - [ ] 빌드 도구 사용
- 실행 방식 :
  - 브라우저에서 `index.html` 파일을 직접 실행할 수 있어야 함
  - 별도의 서버 프로그램 없이 동작하도록 구현
- 외부 라이브러리 :
  - PDF.js : PDF 파일 분석 및 페이지 렌더링
  - JSZip : 여러 JPG 및 로그 파일을 ZIP으로 묶는 기능
- 외부 라이브러리 로딩 :
  - CDN 방식 사용 가능
  - 단, 단일 HTML 파일 구조를 유지할 것
- 지원 브라우저 :
  - Google Chrome 최신 버전
  - Microsoft Edge 최신 버전
  - Safari 최신 버전은 가능한 범위에서 지원
- 인터넷 연결 :
  - 기본적으로 클라이언트 측에서 PDF 변환
  - PDF 파일 자체를 외부 서버로 업로드하지 않음
  - CDN 방식의 라이브러리를 사용하는 경우 최초 실행 시 인터넷 연결이 필요할 수 있음
  - 가능한 경우 라이브러리를 단일 HTML에 포함하여 완전 오프라인 실행이 가능하도록 설계

------------------------------------------------

## 2. 프로그램 목적

PDF 파일을 JPG 이미지 파일로 변환하는 웹 기반 도구를 제작한다.

Python/Tkinter 기반 기존 PDF → JPG 변환 프로그램의 주요 기능을 JavaScript 웹앱으로 구현한다.

사용자가 PDF 파일을 선택하거나 웹앱의 드롭존에 PDF 파일을 드래그 앤 드롭하면 브라우저 내부에서 PDF를 분석하고 각 페이지를 JPG 이미지로 변환한다.

변환 과정에서 PDF 파일을 서버로 업로드하지 않고 사용자의 브라우저에서 직접 처리하는 클라이언트 사이드 방식으로 구현한다.

변환 결과는 개별 JPG 파일 또는 ZIP 파일 형태로 다운로드할 수 있도록 한다.

## 3. 주요 기능

### 필수 기능

① PDF 파일 선택

- 파일 선택 버튼을 제공한다.
- `.pdf` 파일만 선택할 수 있도록 한다.
- 여러 개의 PDF 파일을 동시에 선택할 수 있도록 한다.
- 선택된 PDF 파일 목록을 화면에 표시한다.
- 동일한 PDF 파일이 중복 추가되지 않도록 한다.

② PDF 드래그 앤 드롭

- 화면에 PDF 드롭존을 제공한다.
- PDF 파일을 드래그하여 드롭존에 놓으면 자동으로 파일 목록에 추가한다.
- 여러 PDF 파일을 동시에 드롭할 수 있도록 한다.
- PDF가 아닌 파일을 드롭한 경우 변환 대상에서 제외하고 사용자에게 안내한다.

③ 입력 방식

다음 두 가지 입력 방식을 제공한다.

- 개별 PDF 파일 선택
- 폴더 선택

개별 파일 모드에서는 여러 PDF 파일을 선택할 수 있다.

폴더 모드에서는 선택한 폴더에 포함된 PDF 파일을 변환 대상으로 구성한다.

단, 브라우저의 파일 시스템 보안 정책으로 인해 일반적인 데스크톱 프로그램과 동일하게 임의의 로컬 폴더를 직접 탐색하거나 접근할 수 없는 경우에는 브라우저가 제공하는 파일/디렉터리 선택 API의 범위 내에서 구현한다.

④ DPI 설정

다음 DPI를 선택할 수 있도록 한다.

- 72 DPI
- 150 DPI
- 200 DPI
- 300 DPI
- 400 DPI

기본값은 300 DPI로 설정한다.

PDF.js의 Canvas 렌더링 배율을 DPI에 따라 계산한다.

⑤ 페이지 범위 지정

개별 파일 변환 시 원하는 페이지만 변환할 수 있도록 한다.

예:

- `1-3`
- `1,3,5`
- `1-3,5,7-9`

페이지 번호는 1부터 시작한다.

범위가 중복되는 경우 동일한 페이지를 한 번만 변환한다.

잘못된 입력은 변환 시작 전에 검증한다.

⑥ PDF 페이지 수 확인

변환 시작 전에 각 PDF 파일의 페이지 수를 확인한다.

페이지 범위를 지정한 경우 실제 PDF 페이지 수와 비교한다.

존재하지 않는 페이지가 지정된 경우 해당 페이지를 오류 로그에 기록한다.

⑦ PDF → JPG 변환

PDF.js를 이용하여 PDF 페이지를 Canvas에 렌더링한다.

Canvas를 JPEG Blob으로 변환하여 JPG 파일을 생성한다.

PDF 전체 페이지 변환과 선택 페이지 변환을 모두 지원한다.

⑧ 파일명 생성

PDF 파일명을 기준으로 JPG 파일명을 생성한다.

전체 페이지 변환 시:

- 페이지가 1개인 PDF
  - `document.jpg`

- 페이지가 여러 개인 PDF
  - `document_1.jpg`
  - `document_2.jpg`
  - `document_3.jpg`

일부 페이지만 변환하는 경우:

- `document_p1.jpg`
- `document_p3.jpg`
- `document_p5.jpg`

⑨ 파일명 충돌 방지

서로 다른 PDF에서 동일한 출력 파일명이 발생할 경우 파일명이 중복되지 않도록 한다.

예:

- `document_1.jpg`
- `document_1_dup1.jpg`
- `document_1_dup2.jpg`

⑩ 진행률 표시

전체 변환 페이지 수를 기준으로 ProgressBar를 표시한다.

예:

`진행 상황: 15 / 40 페이지 처리 중`

변환 페이지가 완료될 때마다 ProgressBar를 갱신한다.

⑪ 변환 취소

변환 중 `취소` 버튼을 제공한다.

취소 요청 이후 현재 처리 중인 페이지는 가능한 범위에서 마무리하고 이후 작업을 중단한다.

취소 상태를 화면에 표시한다.

⑫ 오류 처리

다음 오류를 개별적으로 처리한다.

- PDF 파일을 읽을 수 없는 경우
- 손상된 PDF
- 비밀번호로 보호된 PDF
- 존재하지 않는 페이지를 요청한 경우
- PDF.js 렌더링 오류
- JPG 변환 오류
- 브라우저 메모리 부족 등의 오류

특정 페이지에서 오류가 발생하더라도 가능한 경우 전체 작업을 중단하지 않고 다음 페이지를 계속 처리한다.

⑬ 오류 로그

오류가 발생한 경우 다음 정보를 기록한다.

- PDF 파일명
- 페이지 번호
- 오류 내용

변환이 완료되면 `error_log.txt` 파일을 생성하여 다운로드할 수 있도록 한다.

오류가 없는 경우에는 오류 로그 파일을 생성하지 않을 수 있다.

⑭ 변환 결과 다운로드

변환된 JPG 파일을 다운로드할 수 있도록 한다.

여러 파일을 변환한 경우에는 기본적으로 ZIP 파일로 묶어서 다운로드한다.

예:

`converted_files.zip`

ZIP 내부에 JPG 파일과 필요한 경우 `error_log.txt`를 포함한다.

⑮ 결과 요약

변환 완료 후 다음 정보를 표시한다.

- 전체 PDF 파일 수
- 성공한 PDF 파일 수
- 실패한 PDF 파일 수
- 전체 변환 페이지 수
- 성공한 페이지 수
- 실패한 페이지 수
- 변환 결과 다운로드 버튼
- 오류 로그 다운로드 버튼

### 선택 기능

① 변환 결과 미리보기

변환된 JPG 이미지를 웹앱 내부에서 미리볼 수 있도록 한다.

② JPG 품질 설정

JPEG 품질을 0.1~1.0 범위에서 조절할 수 있도록 한다.

기본값은 0.9로 설정한다.

③ 개별 JPG 다운로드

ZIP 파일뿐만 아니라 각 JPG 파일을 개별적으로 다운로드할 수 있도록 한다.

④ 선택한 PDF 제거

파일 목록에서 특정 PDF를 선택하여 제거할 수 있도록 한다.

⑤ 전체 목록 삭제

선택된 PDF 목록을 한 번에 삭제할 수 있도록 한다.

⑥ PDF 파일 정보 표시

각 PDF에 대해 다음 정보를 표시한다.

- 파일명
- 파일 크기
- 페이지 수
- 변환 대상 페이지 수
- 상태

⑦ Web Worker 사용

PDF 변환 작업으로 인해 브라우저 UI가 멈추는 것을 최소화하기 위해 필요한 경우 Web Worker를 활용한다.

단일 HTML 구조를 유지하면서 Worker 코드를 Blob URL 또는 인라인 Worker 방식으로 구성할 수 있다.

⑧ File System Access API

Chrome/Edge 등 지원 브라우저에서는 사용자가 선택한 폴더에 변환 결과를 직접 저장할 수 있도록 선택적으로 지원한다.

지원하지 않는 브라우저에서는 ZIP 다운로드 방식으로 자동 전환한다.

## 4. 사용자 작업 순서

1. 웹앱을 실행한다.

2. PDF 파일을 파일 선택 버튼으로 선택하거나 드롭존에 드래그 앤 드롭한다.

3. 선택된 PDF 파일 목록을 확인한다.

4. 필요한 경우 변환할 PDF 파일을 제거한다.

5. DPI를 선택한다.

6. 필요한 경우 일부 페이지만 변환 옵션을 활성화한다.

7. 페이지 범위를 입력한다.

8. `변환 시작` 버튼을 클릭한다.

9. 웹앱이 PDF 페이지 수를 확인하고 변환 가능한 페이지를 계산한다.

10. PDF.js가 각 페이지를 Canvas에 렌더링한다.

11. Canvas를 JPG Blob으로 변환한다.

12. ProgressBar와 현재 처리 상태를 갱신한다.

13. 오류가 발생한 페이지는 로그에 기록하고 가능한 경우 다음 페이지를 계속 처리한다.

14. 모든 변환이 완료되면 결과 요약을 표시한다.

15. `ZIP 다운로드` 버튼을 클릭하여 변환된 JPG 파일을 다운로드한다.

16. 오류가 발생한 경우 `error_log.txt`도 다운로드할 수 있도록 한다.

`[완료] document.pdf - 12페이지 성공`

`[오류] sample.pdf - 페이지 5`

- 초기화 버튼

## 7. 데이터 저장 및 상태 관리

- 데이터 저장 필요 여부 :
  - [ ] 영구 저장
  - [x] 변환 작업 중 임시 상태만 유지

- 저장 방식 :
  - [ ] localStorage
  - [ ] IndexedDB
  - [ ] 서버/백엔드
  - [x] 브라우저 메모리

- PDF 원본 파일을 서버에 업로드하지 않는다.

- 새로고침 시 데이터 유지 :
  - [ ] 필요
  - [x] 필요 없음

## 10. 성능 요구사항

- PDF 파일 자체를 서버에 업로드하지 않는다.
- 브라우저에서 직접 PDF를 처리한다.
- 페이지 단위로 변환한다.
- 변환 중 UI가 장시간 멈추지 않도록 한다.
- 대용량 PDF 처리 시 메모리 사용량을 고려한다.
- 400 DPI와 같이 높은 해상도를 사용하는 경우 Canvas 크기 증가에 따른 메모리 문제를 고려한다.
- 여러 PDF를 동시에 무리하게 렌더링하지 않는다.
- 필요할 경우 Web Worker를 이용하여 변환 작업을 분리한다.

### 병렬 처리

Python 버전에서는 ThreadPoolExecutor를 이용하여 파일 단위 병렬 변환을 수행한다.

웹 버전에서는 동일한 개념을 무조건 그대로 적용하지 않는다.

브라우저의 메모리 사용량과 Canvas 렌더링 비용을 고려하여 다음 우선순위로 구현한다.

1. 기본적으로 안정적인 순차 페이지 처리
2. 필요 시 PDF 단위 병렬 처리
3. Web Worker를 이용한 백그라운드 처리
4. 과도한 병렬 처리 방지

## 15. Python 프로그램과 웹앱의 기능 대응 원칙

기존 Python 프로그램의 기능을 최대한 유지하되, 브라우저 환경에서 구현이 불가능하거나 부적합한 기능은 웹 환경에 맞게 변경한다.

### 유지해야 하는 핵심 기능

- 폴더/파일 입력 구분
- 여러 PDF 선택
- 드래그 앤 드롭
- DPI 설정
- 전체 페이지 변환
- 선택 페이지 변환
- 페이지 범위 입력
- 페이지 수 사전 확인
- ProgressBar
- 변환 취소
- PDF별/페이지별 오류 처리
- 오류 로그
- 파일명 충돌 방지
- 변환 결과 요약
- JPG 다운로드

### 웹 환경에 맞게 변경해야 하는 기능

Python의 로컬 출력 폴더 직접 저장 방식은 브라우저의 파일 시스템 보안 정책을 고려하여 구현한다.

기본 출력 방식은 ZIP 다운로드로 한다.

Chrome/Edge 등 File System Access API를 지원하는 브라우저에서는 선택적으로 사용자가 지정한 폴더에 직접 저장할 수 있도록 확장한다.

Python의 `os.startfile()`, macOS `open`, Linux `xdg-open`과 같은 OS별 출력 폴더 열기 기능은 웹앱에서 동일하게 구현하지 않는다.

대신 `다운로드 폴더에서 확인` 또는 브라우저의 다운로드 기능을 이용하도록 한다.

## 16. 최종 개발 목표

최종 결과물은 별도의 Python 설치나 서버 프로그램 없이 브라우저에서 실행할 수 있는 **클라이언트 사이드 PDF → JPG 변환 웹앱**으로 제작한다.

사용자의 PDF 파일은 외부 서버로 전송하지 않는다.

PDF 분석과 JPG 변환은 가능한 한 사용자의 PC 브라우저 내부에서 수행한다.

단순한 기능 시연용 코드가 아니라 실제로 반복해서 사용할 수 있는 업무용 웹 유틸리티를 목표로 한다.
