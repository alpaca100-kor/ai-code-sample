# 웹 브라우저 기반 JavaScript 앱 제작 요청

## 1. 개발 환경

- 언어 : HTML / CSS / JavaScript
- 프레임워크 : 
  - [x] Vanilla JS (프레임워크 없음)
  - [ ] React
  - [ ] Vue
  - [ ] 기타 :
- 파일 구성 :
  - [x] 단일 HTML 파일 (CSS/JS 인라인 포함, 바로 열어서 실행)
  - [ ] 별도 파일 (index.html + style.css + script.js)
  - [ ] 빌드 도구 사용 (Vite 등)
- 외부 라이브러리 : 사용하지 않음
- 지원 브라우저 : 최신 버전의 Chrome / Edge / Safari
- 인터넷 연결 필요 여부 : 오프라인 동작 필요
- 실행 환경 : 웹 브라우저에서 HTML 파일을 직접 열어 실행할 수 있어야 함
- 서버/백엔드 : 사용하지 않음

## 2. 프로그램 목적

PNG 이미지의 배경 또는 특정 색상 영역을 사용자가 클릭하여 투명하게 제거할 수 있는 웹 기반 이미지 편집기를 제작한다.

기존 Python 프로그램의 '매직완드' 기능을 웹 브라우저에서 구현한다.

사용자가 PNG 이미지를 불러온 후 이미지의 특정 지점을 클릭하면 클릭한 픽셀의 RGB 색상을 기준으로 유사한 색상의 픽셀을 탐색하고 해당 영역의 Alpha 값을 0으로 변경하여 투명하게 만든다.

사용자는 감도(허용 오차)를 0~100 범위에서 조절할 수 있으며, '인접 영역만 선택' 기능을 통해 클릭한 영역과 연결된 영역만 제거하거나 이미지 전체에서 조건에 맞는 색상을 제거할 수 있어야 한다.

모든 이미지 처리는 브라우저 내부에서 수행하며 서버로 이미지를 업로드하지 않는다.

## 3. 주요 기능

### 필수 기능

① PNG 이미지 파일 열기

- 파일 열기 버튼을 제공한다.
- PNG 파일을 선택하면 이미지를 불러온다.
- 파일을 브라우저 화면으로 드래그 앤 드롭하여 불러올 수도 있어야 한다.
- PNG 이외의 파일을 선택한 경우 오류 또는 안내 메시지를 표시한다.
- 이미지를 불러오면 원본 ImageData와 현재 편집 ImageData를 별도로 보관한다.

② 매직완드 방식의 색상 영역 제거

- 사용자가 이미지의 특정 픽셀을 클릭한다.
- 클릭한 픽셀의 RGB 값을 기준 색상으로 사용한다.
- 이미지의 각 픽셀과 기준 색상 사이의 RGB 유클리드 거리를 계산한다.
- 설정된 허용 오차 이하의 픽셀을 선택한다.
- 선택된 픽셀의 Alpha 값을 0으로 변경한다.
- RGB 값 자체는 변경하지 않는다.
- 이미 투명한 픽셀을 클릭한 경우에는 아무 작업도 하지 않는다.

③ 감도(허용 오차) 조절

- 감도 슬라이더의 범위는 0~100으로 설정한다.
- 기본값은 20으로 설정한다.
- 0은 기준 픽셀과 동일한 RGB 색상만 선택한다.
- 값이 증가할수록 더 넓은 색상 범위를 선택한다.
- 100은 최대 RGB 색상 거리까지 허용하도록 한다.
- 현재 감도 값을 숫자로 화면에 표시한다.

④ 인접 영역만 선택

- '인접 영역만 선택' 체크박스를 제공한다.
- 기본값은 활성화한다.
- 활성화된 경우 클릭한 픽셀과 4방향으로 연결된 조건 만족 영역만 선택한다.
- 비활성화된 경우 이미지 전체에서 조건을 만족하는 픽셀을 선택한다.
- 인접 영역 탐색은 BFS 또는 DFS 기반 Flood Fill 알고리즘을 사용한다.
- 대각선 방향은 연결된 영역으로 간주하지 않는다.

⑤ 실행 취소 / 다시 실행

- 실행 취소 기능을 제공한다.
- 다시 실행 기능을 제공한다.
- 최대 15개의 편집 상태를 저장한다.
- 새로운 편집 작업을 수행하면 Redo 상태는 초기화한다.
- 단축키를 제공한다.
  - Ctrl+Z : 실행 취소
  - Ctrl+Y : 다시 실행
- 실행 취소 또는 다시 실행 버튼은 수행할 수 있는 작업이 없으면 비활성화한다.

⑥ 원본으로 초기화

- 초기화 버튼을 제공한다.
- 초기화 전에 사용자 확인을 요청한다.
- 확인하면 현재 이미지를 최초로 불러온 상태로 복원한다.
- 초기화 작업 역시 Undo 대상에 포함한다.

⑦ 확대 / 축소

- 확대 버튼을 제공한다.
- 축소 버튼을 제공한다.
- 화면 맞춤 버튼을 제공한다.
- 기본 확대 비율은 100%로 한다.
- 최소 확대 비율은 5%로 한다.
- 최대 확대 비율은 2000%로 한다.
- 확대/축소 비율을 화면에 표시한다.
- Ctrl + 마우스 휠로 확대/축소할 수 있도록 한다.
- 일반 마우스 휠은 이미지 영역을 스크롤하도록 한다.
- Shift + 마우스 휠은 가로 방향으로 스크롤할 수 있도록 한다.

⑧ 투명 영역 표시

- 투명해진 영역은 체크무늬 배경으로 표시한다.
- PNG의 Alpha 값이 0인 영역과 실제 체크무늬 배경을 시각적으로 구분할 수 있도록 한다.
- 체크무늬는 이미지 자체에 저장하지 않는다.
- PNG 저장 시 체크무늬 배경은 저장되지 않아야 한다.

⑨ PNG 저장

- 저장 버튼을 제공한다.
- 현재 편집된 이미지를 PNG 형식으로 저장한다.
- 투명도가 유지되어야 한다.
- 체크무늬 배경은 저장하지 않는다.
- 브라우저의 다운로드 기능을 이용한다.
- 기본 파일명은 원본 파일명 뒤에 `_transparent`를 붙이는 방식으로 한다.
- 예:
  - `image.png`
  - `image_transparent.png`
- Ctrl+S 단축키를 지원한다.

⑩ 상태 표시

하단 상태 표시 영역에 다음 정보를 표시한다.

- 현재 파일명
- 이미지 크기
- 현재 확대/축소 비율
- 최근 수행 작업
- 투명하게 변경한 픽셀 수

예:

`sample.png | 1920 × 1080px | 확대/축소 100% | 12,345개 픽셀을 투명하게 변경했습니다.`

### 선택 기능

① 이미지 정보 표시

- 이미지의 가로/세로 크기
- 전체 픽셀 수
- 현재 투명 픽셀 수

② 키보드 단축키

- Ctrl+O : 이미지 열기
- Ctrl+S : PNG 저장
- Ctrl+Z : 실행 취소
- Ctrl+Y : 다시 실행
- Ctrl+마우스 휠 : 확대/축소

③ 작업 중 처리 상태 표시

- 대용량 이미지에서 매직완드 연산을 수행하는 동안 처리 중임을 표시한다.
- 처리 중에는 중복 클릭이나 추가 편집을 방지한다.

④ Web Worker 확장 가능 구조

- 이미지 처리 로직은 향후 Web Worker로 분리할 수 있도록 함수 단위로 구성한다.
- 초기 버전에서는 일반 JavaScript 실행으로 구현하되, 구조적으로 Worker 적용이 가능해야 한다.

## 4. 사용자 작업 순서

1. 웹 앱을 실행한다.
2. '파일 열기' 버튼을 클릭하거나 PNG 파일을 앱 영역으로 드래그 앤 드롭한다.
3. 이미지가 캔버스에 표시된다.
4. 감도 슬라이더를 조절한다.
5. 필요한 경우 '인접 영역만 선택' 옵션을 켜거나 끈다.
6. 이미지에서 투명하게 만들 배경 영역을 클릭한다.
7. 선택된 색상 영역의 Alpha 값이 0으로 변경된다.
8. 필요한 경우 감도 값을 변경하여 다시 클릭한다.
9. 실행 취소 또는 다시 실행을 이용하여 작업을 수정한다.
10. '화면 맞춤', 확대, 축소 기능을 이용하여 이미지를 확인한다.
11. '저장' 버튼 또는 Ctrl+S를 눌러 PNG 파일로 저장한다.

## 5. 화면 구성 (레이아웃)

### 상단

- 애플리케이션 제목
- 파일 열기 버튼
- 저장 버튼
- 실행 취소 버튼
- 다시 실행 버튼
- 초기화 버튼
- 감도 슬라이더
- 감도 숫자 표시
- 인접 영역만 선택 체크박스
- 축소 버튼
- 확대 비율 표시
- 확대 버튼
- 화면 맞춤 버튼

### 중앙

- 이미지 편집 영역
- HTML Canvas를 이용하여 이미지를 표시한다.
- 어두운 회색 계열의 작업 영역을 사용한다.
- 이미지가 화면보다 큰 경우 가로/세로 스크롤이 가능해야 한다.
- 투명 영역에는 체크무늬 배경을 표시한다.
- 이미지가 없는 상태에서는 사용자가 파일을 열거나 드래그 앤 드롭할 수 있다는 안내 문구를 표시한다.

### 하단

상태 표시줄을 배치한다.

다음 정보를 표시한다.

- 파일명
- 이미지 해상도
- 확대/축소 비율
- 최근 작업 결과
- 오류 및 안내 메시지

### 반응형 대응

- 모바일 대응 필요 여부 : 기본적으로 데스크톱 우선
- 화면 크기별 레이아웃 변화 :
  - 데스크톱에서는 상단 도구 모음을 한 줄로 표시한다.
  - 좁은 화면에서는 도구 모음이 여러 줄로 자동 배치될 수 있도록 한다.
  - 이미지 편집 영역은 남은 화면을 최대한 사용한다.
  - 캔버스 영역은 화면 크기에 따라 자동으로 확대/축소한다.
- 최소 지원 화면 크기 : 720 × 520px 수준을 목표로 한다.

## 7. 데이터 저장 및 상태 관리

- 데이터 저장 필요 여부 : 영구 저장은 필요하지 않음
- 저장 방식 :
  - [ ] 브라우저 저장 (localStorage / IndexedDB)
  - [ ] 서버/백엔드 연동
  - [x] 저장 없음 (세션 중에만 유지)
- 새로고침 시 데이터 유지 필요 여부 : 아니오
- 여러 기기/브라우저 간 동기화 필요 여부 : 아니오
- 원본 이미지 : 메모리에서 유지
- 현재 편집 이미지 : 메모리에서 유지
- Undo Stack : 최대 15개 상태 유지
- Redo Stack : 사용자 작업에 따라 동적으로 관리
- 이미지 파일 자체를 서버로 업로드하지 않는다.

## 9. 예외 처리 및 오류 대응

### 입력값이 잘못된 경우

- PNG 이외의 파일을 불러오려고 하면 안내 메시지를 표시한다.
- 손상되었거나 브라우저에서 읽을 수 없는 이미지이면 오류 메시지를 표시한다.
- 이미지가 로드되지 않은 상태에서 편집 기능을 실행하면 동작하지 않도록 한다.

### 이미지 처리 오류

- 이미지 좌표가 유효하지 않으면 아무 작업도 하지 않는다.
- 이미 투명한 픽셀을 클릭하면 작업을 수행하지 않는다.
- 선택 영역이 존재하지 않으면 안내 메시지를 표시한다.

### 대용량 이미지

- 지나치게 큰 이미지에서 브라우저가 과도한 메모리를 사용하는 것을 방지한다.
- 필요할 경우 이미지 크기 제한 또는 경고를 제공할 수 있도록 구조를 구성한다.

### 데이터가 없을 경우

이미지가 없는 상태에서는 중앙 편집 영역에 다음과 같은 안내를 표시한다.

`PNG 파일을 열거나 이곳으로 드래그하세요.`

### 오류 메시지 표시 방식

- 일반 안내 : 화면 하단 상태 표시줄
- 사용자에게 확인이 필요한 작업 : 모달 또는 커스텀 확인 대화상자
- 심각한 처리 오류 : 화면 내 오류 메시지
- 개발 단계의 디버깅 : `console.error()`

기본적으로 브라우저의 `alert()` 남용은 피하고 앱 내부 메시지 UI를 우선한다.

## 10. 성능 요구사항

- 대용량 데이터 처리 필요 여부 : 있음
- 일반적인 PNG 이미지에서 원활하게 동작해야 한다.
- 픽셀 단위 연산은 Typed Array를 사용한다.
- 불필요한 Canvas 전체 재렌더링을 최소화한다.
- 이미지 확대/축소 시 원본 ImageData를 변경하지 않는다.
- Undo/Redo 상태 저장 시 필요한 데이터만 관리하도록 한다.
- 목록 가상 스크롤 : 해당 없음
- 이미지/파일 업로드 용량 제한 : 초기 버전에서는 브라우저 메모리를 고려하여 합리적인 크기의 PNG를 대상으로 한다.
- 대형 이미지에서 매직완드 연산으로 브라우저 UI가 장시간 멈추지 않도록 처리 상태를 표시한다.
- 향후 필요하면 매직완드 픽셀 연산을 Web Worker로 분리할 수 있도록 설계한다.

## 12. 코드 작성 규칙

- HTML, CSS, JavaScript의 역할을 논리적으로 분리한다.

  - JavaScript : 상태 관리, 이미지 처리, 이벤트 처리

- 일관된 camelCase 네이밍 규칙을 사용한다.
- 전역 변수 사용을 최소화한다.
- 오류 처리를 포함한다.
- 향후 Web Worker로 이미지 처리 로직을 분리할 수 있도록 구성한다.

### 품질 목표

단순히 기능이 동작하는 수준의 예제 코드가 아니라 실제 사용 및 배포를 고려한 수준으로 작성한다.

특히 이미지 처리 로직, Canvas 렌더링, 파일 처리, Undo/Redo, UI 상태 관리를 서로 분리하여 유지보수가 용이한 구조로 작성한다.

향후 브러시 지우개, 선택 영역 미리보기, 선택 영역 테두리 표시, Web Worker 기반 고속 처리 등의 기능을 추가할 수 있도록 확장 가능한 구조를 사용한다.
