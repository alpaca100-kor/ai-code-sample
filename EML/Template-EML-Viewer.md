# 웹 브라우저 기반 JavaScript 앱 제작 요청

## 1. 개발 환경
- 언어 : HTML / CSS / JavaScript
- 프레임워크 : (택 1)
  - [x] Vanilla JS (프레임워크 없음)
  - [ ] React
  - [ ] Vue
  - [ ] 기타 :
- 파일 구성 : (택 1)
  - [x] 단일 HTML 파일 (CSS/JS 인라인 포함, 바로 열어서 실행)
  - [ ] 별도 파일 (index.html + style.css + script.js)
  - [ ] 빌드 도구 사용 (Vite 등)
- 외부 라이브러리 :
  - MIME/EML 파싱 라이브러리 1개 사용 권장
  - HTML Sanitizer 라이브러리 사용 권장
  - CDN 방식으로 사용할 수 있도록 구성
  - 불필요한 라이브러리는 사용하지 않음
- 지원 브라우저 : 최신 Chrome / Edge / Safari
- 구버전 브라우저 지원 : 불필요
- 인터넷 연결 필요 여부 :
  - 기본적으로 EML 파일 열람 자체는 오프라인에서도 가능하도록 설계
  - 외부 CDN 라이브러리를 사용하는 경우 최초 라이브러리 로딩에는 인터넷이 필요할 수 있으므로, 가능하면 배포 시 라이브러리를 프로젝트에 포함하여 완전한 오프라인 동작을 고려
- 배포 환경 : GitHub Pages
- 서버/백엔드 : 사용하지 않음
- 개인정보 보호 : EML 파일 및 이메일 내용은 외부 서버로 전송하지 않고 브라우저에서 로컬 처리

## 2. 프로그램 목적

사용자가 보유하고 있는 `.eml` 이메일 파일을 별도의 이메일 프로그램이나 전용 프로그램을 설치하지 않고 웹 브라우저에서 직접 열람할 수 있도록 하는 클라이언트 사이드 웹앱을 제작합니다.

사용자가 EML 파일을 선택하거나 웹앱에 드래그 앤 드롭하면 JavaScript가 브라우저 내부에서 EML의 MIME 구조를 분석합니다.

분석된 이메일에서 발신자, 수신자, 참조, 제목, 날짜, 본문, HTML 본문 및 첨부파일 등의 정보를 추출하여 일반적인 이메일 프로그램과 유사한 형태로 화면에 표시합니다.

특히 개인정보가 포함될 가능성이 높은 이메일 파일을 서버로 업로드하지 않고 브라우저만으로 처리하는 것을 핵심 설계 원칙으로 합니다.

## 3. 주요 기능

### 필수 기능

① EML 파일 선택

파일 선택 버튼을 통해 사용자의 PC에서 `.eml` 파일을 선택할 수 있도록 합니다.

② EML 파일 드래그 앤 드롭

웹앱의 지정된 영역에 EML 파일을 드래그 앤 드롭하여 불러올 수 있도록 합니다.

③ 이메일 정보 표시

EML에서 다음 정보를 추출하여 표시합니다.

- 제목(Subject)
- 발신자(From)
- 수신자(To)
- 참조(Cc)
- 날짜(Date)
- Reply-To
- 이메일 본문

정보가 존재하지 않는 항목은 화면에 불필요하게 표시하지 않습니다.

④ HTML / 일반 텍스트 이메일 본문 표시

이메일에 HTML 본문이 포함되어 있다면 HTML 이메일 형태로 표시합니다.

HTML 본문이 없는 경우 일반 텍스트 본문을 표시합니다.

HTML 이메일에 포함된 악성 JavaScript 등이 실행되지 않도록 HTML Sanitizing 및 보안 처리를 반드시 적용합니다.

⑤ 첨부파일 확인 및 다운로드

EML에 포함된 첨부파일을 추출하여 다음 정보를 표시합니다.

- 파일명
- 파일 형식
- 파일 크기
- 다운로드 버튼

브라우저에서 직접 열람 가능한 이미지 및 PDF 등은 가능하면 미리보기 기능을 제공합니다.

### 선택 기능

① 여러 EML 파일 열기

여러 개의 EML 파일을 한 번에 선택하여 이메일 목록으로 표시할 수 있도록 확장 가능한 구조로 설계합니다.

단, 초기 버전에서는 단일 EML 파일 열람을 우선 구현합니다.

② 이메일 정보 복사

제목, 발신자, 수신자, 본문 등의 정보를 클립보드에 복사할 수 있는 기능을 제공합니다.

③ EML 파일명 표시

현재 열람 중인 EML 파일의 이름을 화면에 표시합니다.

④ 본문 검색

현재 이메일 본문에서 특정 문자열을 검색할 수 있도록 확장 가능한 구조로 설계합니다.

⑤ 첨부파일 미리보기

PDF, JPG, PNG 등의 브라우저 지원 파일을 별도의 다운로드 없이 미리볼 수 있도록 합니다.

## 4. 사용자 작업 순서

1. 사용자가 웹앱에 접속합니다.
2. `EML 파일 열기` 버튼을 클릭하거나 EML 파일을 드래그 앤 드롭합니다.
3. JavaScript가 선택된 파일을 브라우저 내부에서 읽습니다.
4. EML MIME 구조를 분석하여 이메일 헤더, 본문 및 첨부파일을 추출합니다.
5. 추출된 이메일 정보를 이메일 열람 화면에 표시합니다.
6. 사용자는 이메일 본문을 읽고 첨부파일을 확인합니다.
7. 필요한 경우 첨부파일을 다운로드하거나 본문/메일 정보를 복사합니다.
8. 다른 EML 파일을 선택하면 기존 이메일을 새로운 이메일로 교체하여 표시합니다.

## 6. 세부 동작

### `EML 파일 열기` 버튼을 클릭하면

↓

브라우저의 파일 선택창을 실행합니다.

↓

`.eml` 파일만 선택할 수 있도록 파일 필터를 적용합니다.

↓

파일을 JavaScript의 `File API`를 이용하여 읽습니다.

↓

EML 파서가 파일의 MIME 구조를 분석합니다.

↓

이메일 헤더와 본문을 추출합니다.

↓

화면에 이메일 정보를 표시합니다.

---

### EML 파일을 드래그 앤 드롭하면

↓

드래그된 파일의 확장자와 MIME 정보를 확인합니다.

↓

EML 파일인 경우 파일을 읽습니다.

↓

EML 파싱을 수행합니다.

↓

이메일 열람 화면을 표시합니다.

---

### HTML 본문이 존재하면

↓

HTML 본문을 추출합니다.

↓

HTML Sanitizer를 통해 위험한 요소를 제거합니다.

↓

안전한 HTML만 이메일 본문 영역에 표시합니다.

↓

이메일 본문의 JavaScript가 웹앱의 권한으로 실행되지 않도록 차단합니다.

---

### 일반 텍스트 본문만 존재하면

↓

일반 텍스트 본문을 추출합니다.

↓

HTML로 변환할 때 특수문자를 적절하게 escape합니다.

↓

줄바꿈을 유지하여 이메일 본문을 표시합니다.

---

### 첨부파일이 존재하면

↓

MIME 구조에서 첨부파일을 추출합니다.

↓

파일명, Content-Type, 파일 크기 등의 정보를 확인합니다.

↓

브라우저의 `Blob` 및 `URL.createObjectURL()`을 이용하여 파일을 임시로 사용할 수 있도록 합니다.

↓

파일 유형에 따라 다음과 같이 처리합니다.

- 이미지 → 이미지 미리보기
- PDF → 브라우저 PDF 뷰어 또는 새 탭에서 열기
- 기타 파일 → 다운로드

---

### `다운로드` 버튼을 클릭하면

↓

해당 첨부파일의 Blob을 이용하여 브라우저의 다운로드 기능을 실행합니다.

↓

서버로 파일을 업로드하지 않습니다.

---

### 새로운 EML 파일을 선택하면

↓

기존 이메일 상태를 초기화합니다.

↓

새로운 EML 파일을 파싱합니다.

↓

새로운 이메일 정보를 표시합니다.

↓

이전에 생성한 `Object URL`이 있다면 `URL.revokeObjectURL()`로 정리합니다.

## 7. 데이터 저장 및 상태 관리

- 데이터 저장 필요 여부 : 없음
- 저장 방식 :
  - [ ] 브라우저 저장 (localStorage / IndexedDB)
  - [ ] 서버/백엔드 연동
  - [x] 저장 없음 (세션 중에만 유지)

- 새로고침 시 데이터 유지 필요 여부 : 아니오
- 여러 기기/브라우저 간 동기화 필요 여부 : 아니오

EML 파일과 이메일 내용은 기본적으로 저장하지 않습니다.

사용자가 선택한 EML 파일은 브라우저 메모리에서 처리하며 웹서버 또는 외부 API로 전송하지 않습니다.

특히 `localStorage`나 `IndexedDB`에도 이메일 내용을 자동으로 저장하지 않습니다.

## 8. 디자인 및 스타일

- 디자인 톤 : 미니멀하고 깔끔한 업무용 도구
- ALPACA TOOLS 기존 디자인과 일관성 유지
- 이메일 클라이언트와 유사하지만 복잡하지 않은 UI
- 불필요한 장식 최소화
- 이메일 본문의 가독성을 최우선으로 설계
- 다크/라이트 모드 지원 여부 : 기존 ALPACA TOOLS 디자인 시스템을 따름
- 참고할 만한 디자인/서비스 :
  - 일반적인 웹메일 UI
  - Gmail / Outlook의 이메일 열람 화면을 참고하되 그대로 복제하지 않음
- 폰트/아이콘 사용 여부 :
  - 기존 ALPACA TOOLS에서 사용하는 폰트 체계를 우선 사용
  - 아이콘은 기존 프로젝트에서 사용하는 아이콘 체계가 있다면 재사용
  - 새로운 아이콘 라이브러리는 꼭 필요한 경우에만 사용

### 중요

이메일 본문은 발신자가 만든 HTML이므로 웹앱의 전체 UI와 이메일 본문의 CSS가 충돌하지 않도록 격리해야 합니다.

가능하면 이메일 HTML을 별도의 `iframe` 또는 안전한 렌더링 영역에서 표시하는 방식을 검토합니다.

## 9. 예외 처리 및 오류 대응

### 입력값이 잘못된 경우

다음 파일은 열지 않습니다.

- `.eml`이 아닌 파일
- 손상된 EML 파일
- MIME 구조를 정상적으로 분석할 수 없는 파일

화면에 다음과 같이 오류를 표시합니다.

> EML 파일을 열 수 없습니다. 파일이 손상되었거나 지원하지 않는 형식일 수 있습니다.

### 네트워크 오류

핵심 기능은 서버와 통신하지 않으므로 네트워크 오류의 영향을 받지 않도록 설계합니다.

외부 CDN 라이브러리를 사용하는 경우에는 라이브러리를 불러오지 못하면 사용자에게 안내 메시지를 표시합니다.

가능하면 최종 배포본에서는 외부 CDN 의존성을 제거합니다.

### 데이터가 없을 경우

EML 파일에 특정 헤더가 없으면 해당 항목을 빈 값으로 표시하지 않고 숨깁니다.

예를 들어 Cc가 없다면 `Cc` 행 자체를 표시하지 않습니다.

### 본문이 없는 경우

다음과 같이 표시합니다.

> 표시할 이메일 본문이 없습니다.

### 첨부파일이 없는 경우

첨부파일 영역 자체를 숨기거나 다음과 같이 표시합니다.

> 첨부파일이 없습니다.

### 오류 메시지 표시 방식

- [ ] alert
- [x] 화면 내 메시지
- [x] 콘솔 로그는 개발 및 디버깅 목적으로 제한적으로 사용
- [ ] 브라우저 alert 남용 금지

## 10. 성능 요구사항

- 대용량 데이터 처리 필요 여부 : 일반적인 업무 이메일 기준
- 단일 EML 파일의 적정 크기 : 우선 **50MB 이하**를 기준으로 설계
- 대용량 첨부파일을 포함한 EML도 브라우저가 멈추지 않도록 고려
- 불필요한 파일 복사 및 Base64 변환을 최소화
- 첨부파일은 가능하면 `Blob` 기반으로 처리
- `Object URL`은 사용 후 반드시 해제

여러 EML 파일을 지원하는 경우에는 모든 이메일의 본문을 동시에 DOM에 렌더링하지 않고 **선택한 이메일만 렌더링**하도록 설계합니다.

## 11. 접근성 및 사용성 (선택)

- 키보드 조작 지원 필요 여부 : 필요

- 충분한 글자 크기와 명확한 대비 사용
- 이메일 본문과 웹앱 UI의 포커스 이동을 구분

## 12. 코드 작성 규칙

- HTML / CSS / JavaScript 역할별 분리
- `index.html`
- `style.css`
- `script.js`

구조 예시:

```text
eml-viewer/
├─ index.html
├─ style.css
├─ script.js
└─ lib/
    ├─ eml-parser.js
    └─ sanitizer.js
```

실제 프로젝트의 라이브러리 관리 방식에 따라 `lib` 구조는 조정할 수 있습니다.

JavaScript는 다음과 같이 역할별 함수를 분리합니다.

```text
파일 처리
 ├─ handleFileSelect()
 ├─ handleDrop()
 └─ validateFile()

EML 분석
 ├─ parseEML()
 ├─ parseHeaders()
 ├─ extractBody()
 └─ extractAttachments()

화면 처리
 ├─ renderEmail()
 ├─ renderHeader()
 ├─ renderBody()
 └─ renderAttachments()

첨부파일
 ├─ previewAttachment()
 ├─ downloadAttachment()
 └─ revokeObjectUrls()

오류 처리
 └─ showError()
```

- 함수는 하나의 명확한 역할만 수행
- 전역 변수 최소화
- DOM 요소에 대한 직접적인 접근 최소화
- 이벤트 처리와 데이터 처리 로직 분리
- 충분한 주석 작성
- 유지보수가 쉬운 구조
- 예외 처리 포함
- 일관된 camelCase 네이밍 사용
- 사용자 입력 및 EML 내부 데이터는 신뢰하지 않고 항상 검증

## 14. 결과물

### 필수 결과물

- 실행 가능한 `index.html`
- 필요한 EML 파싱 라이브러리
- 필요한 HTML Sanitizer 라이브러리
- README 또는 사용법 문서

### 외부 라이브러리

EML의 MIME 구조는 직접 파서를 처음부터 구현하기보다 검증된 JavaScript MIME/EML 파서 라이브러리를 사용하는 것을 권장합니다.

HTML 이메일을 렌더링할 때는 XSS 방지를 위해 **HTML Sanitizer를 반드시 적용**합니다.

라이브러리를 선정할 때에는 다음 조건을 우선합니다.

- 브라우저에서 직접 실행 가능
- Vanilla JS에서 사용 가능
- npm뿐 아니라 브라우저 배포가 쉬움
- 유지보수가 활발함
- 라이선스가 명확함
- EML/MIME의 한글 인코딩 처리 지원
- 첨부파일 처리 지원

### 앱 사용법

1. 웹 브라우저에서 알파카 EML 뷰어에 접속합니다.
2. `EML 파일 열기` 버튼을 클릭합니다.
3. PC에 저장된 `.eml` 파일을 선택합니다.
4. 또는 EML 파일을 화면의 드롭 영역으로 끌어옵니다.
5. 이메일 제목, 발신자, 수신자, 날짜 및 본문을 확인합니다.
6. 첨부파일이 있다면 파일을 확인하거나 다운로드합니다.

### 핵심 개발 원칙

이 앱은 **"EML 파일을 서버로 업로드하는 웹서비스"가 아니라 "브라우저 자체를 EML 뷰어로 사용하는 웹앱"**으로 개발합니다.

따라서 사용자가 선택한 EML 파일의 데이터가 외부 서버나 API로 전송되지 않도록 합니다.

또한 이메일 HTML은 신뢰할 수 없는 외부 콘텐츠로 취급하고, **XSS·악성 스크립트·위험한 URL·외부 리소스 로딩 등에 대한 보안 처리를 필수적으로 적용**합니다.

최종적으로는 단순히 EML 텍스트를 출력하는 수준이 아니라 **Outlook에서 이메일 하나를 열어보는 것과 유사한 사용성을 제공하는 경량 EML 뷰어**를 목표로 합니다.
