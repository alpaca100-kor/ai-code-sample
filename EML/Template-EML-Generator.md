# 알파카 EML 생성기 상세 개발 설계도

## 1. 개발 환경

- 개발 언어: HTML / CSS / JavaScript
- 프레임워크: Vanilla JS
- 파일 구성: 단일 `index.html`
- HTML / CSS / JavaScript: 모두 하나의 HTML 파일에 포함
- 실행 환경: 최신 Chrome / Edge / Safari
- 구형 브라우저: 지원하지 않음
- 서버 / 백엔드: 사용하지 않음
- 배포: GitHub Pages
- 데이터 처리: 브라우저 내부에서만 처리
- 외부 전송: 이메일 내용이나 첨부파일을 외부 서버로 전송하지 않음
- 결과물: 사용자가 다운로드할 수 있는 `.eml` 파일

핵심 원칙은 실제 이메일을 발송하지 않고, 브라우저에서 MIME 형식의 EML 파일을 생성하여 저장하는 것입니다.

모든 HTML, CSS, JavaScript를 하나의 `index.html`에 포함하여 별도의 파일이나 백엔드 없이 독립적으로 실행할 수 있도록 합니다.

---

## 2. 프로그램 제작 목적

`알파카 EML 생성기`는 사용자가 웹 브라우저에서 이메일 정보를 입력하면 MIME 구조를 가진 `.eml` 파일을 생성하는 웹앱입니다.

주요 목적은 다음과 같습니다.

- EML 파일을 직접 제작
- EML 뷰어 테스트용 파일 생성
- MIME 이메일 구조 학습
- 이메일 샘플 생성
- HTML 이메일 테스트
- 첨부파일이 포함된 EML 테스트 파일 생성
- 한글 제목 및 본문이 포함된 EML 생성
- 안전한 테스트 데이터 제작

특히 앞서 개발한 알파카 EML 뷰어의 테스트 데이터 생성 도구로 활용할 수 있도록 설계합니다.

실제 SMTP 서버나 이메일 계정에 접속하여 메일을 보내는 기능은 구현하지 않습니다.

## 3. 필수 기능

### 3.1 이메일 기본 정보 입력

다음 항목을 입력할 수 있도록 합니다.

- 보낸 사람(From)
- 받는 사람(To)
- 참조(Cc)
- 숨은 참조(Bcc)
- 회신 주소(Reply-To)
- 날짜(Date)
- 제목(Subject)

여러 이메일 주소 입력을 지원하며 쉼표 또는 줄바꿈으로 구분할 수 있도록 합니다.

### 3.2 본문 입력

다음 형태를 지원합니다.

**일반 텍스트 본문**

```text
안녕하세요.

알파카 EML 생성기로 만든 테스트 메일입니다.
```

**HTML 본문**

```html
<h2>알파카 EML 생성기</h2>
<p>HTML 형식의 이메일입니다.</p>
```

텍스트와 HTML을 모두 입력한 경우 `multipart/alternative` 구조로 생성합니다.

### 3.3 첨부파일

사용자의 PC에서 파일을 선택하여 EML에 첨부할 수 있도록 합니다.

- 파일 선택
- 여러 파일 선택
- 드래그 앤 드롭
- 파일명 표시
- 파일 크기 표시
- 파일 제거
- MIME 타입 표시
- 첨부파일 Base64 인코딩

첨부파일은 `multipart/mixed` 구조에 포함합니다.

### 3.4 EML 파일 생성

생성 과정은 다음과 같습니다.

```text
사용자 입력
   ↓
입력값 검증
   ↓
메일 헤더 생성
   ↓
본문 MIME 생성
   ↓
HTML/텍스트 구조 생성
   ↓
첨부파일 Base64 변환
   ↓
MIME multipart 구조 생성
   ↓
CRLF 기준 EML 문자열 생성
   ↓
Blob 생성
   ↓
.eml 파일 다운로드
```

### 3.5 파일명 설정

기본 파일명은 제목을 활용합니다.

예:

`알파카 테스트 메일` → `알파카 테스트 메일.eml`

파일명에 사용할 수 없는 문자는 제거하거나 `_` 등으로 치환합니다.

사용자가 직접 파일명을 지정할 수도 있도록 합니다.

## 6. EML 생성 상세 설계

EML은 이메일 헤더와 MIME 구조를 가진 파일이므로 생성 과정에서 형식을 정확하게 구성해야 합니다.

### 6.1 기본 헤더

```text
From: alpaca@example.com
To: user@example.com
Subject: =?UTF-8?B?...?=
Date: Thu, 08 Oct 2026 14:30:00 +0900
Message-ID: <...>
MIME-Version: 1.0
```

필요한 경우 다음 헤더도 추가합니다.

```text
Cc:
Bcc:
Reply-To:
```

Bcc는 실제 발송을 하지 않는 테스트 파일이라는 특성을 고려하여 결과 EML에 포함할지 명확한 정책을 정합니다. 기본 설계에서는 입력값을 EML에 반영하되 화면에 테스트용 정보임을 안내할 수 있습니다.

### 6.2 한글 헤더 처리

제목이나 표시 이름에 한글 등 비 ASCII 문자가 포함되는 경우 RFC 2047 encoded-word 형식 등을 사용하여 적절하게 인코딩합니다.

### 6.3 줄바꿈

MIME 메시지는 CRLF(`\r\n`)를 기준으로 생성합니다.

```text
Header\r\n
Header\r\n
\r\n
Body\r\n
```

### 6.4 본문 구조

일반 텍스트:

```text
Content-Type: text/plain; charset="UTF-8"
Content-Transfer-Encoding: 8bit
```

HTML:

```text
Content-Type: text/html; charset="UTF-8"
Content-Transfer-Encoding: 8bit
```

텍스트 + HTML:

```text
Content-Type: multipart/alternative;
 boundary="..."
```

구조:

```text
multipart/alternative
 ├─ text/plain
 └─ text/html
```

### 6.5 첨부파일 구조

첨부파일이 존재하면 다음과 같이 구성합니다.

```text
multipart/mixed
 ├─ multipart/alternative
 │   ├─ text/plain
 │   └─ text/html
 ├─ attachment 1
 ├─ attachment 2
 └─ attachment 3
```

첨부파일 예:

```text
Content-Type: application/pdf;
 name="document.pdf"
Content-Disposition: attachment;
 filename="document.pdf"
Content-Transfer-Encoding: base64
```

### 6.6 첨부파일 Base64 처리

```text
File
 ↓
ArrayBuffer
 ↓
Uint8Array
 ↓
Base64
 ↓
MIME body
```

Base64 데이터는 MIME 형식에 맞춰 적절한 길이로 줄바꿈합니다.

대용량 파일은 브라우저 메모리 사용량을 고려하여 처리합니다.

### 6.7 MIME Boundary 생성

`multipart/mixed` 및 `multipart/alternative`에 사용할 boundary는 매번 고유하게 생성합니다.

```text
----=_AlpacaEML_7f4d8c...
```

본문과 충돌할 가능성을 최소화하도록 충분히 긴 값을 사용합니다.

## 7. 데이터 저장 및 개인정보

기본적으로 데이터를 서버에 저장하지 않습니다.

다음 정보는 외부 서버로 전송하지 않습니다.

- 이메일 주소
- 제목
- 본문
- HTML
- 첨부파일

모든 작업은 사용자의 브라우저 내부에서 처리합니다.

```text
사용자 PC
   │
   ├─ 이메일 정보
   ├─ 본문
   └─ 첨부파일
        ↓
     브라우저 JS
        ↓
      EML 생성
        ↓
     사용자 PC에 저장
```

`localStorage`나 `IndexedDB` 등에 이메일 내용을 자동 저장하지 않습니다.

페이지를 새로 고치거나 닫으면 입력 데이터는 기본적으로 사라집니다.

## 10. 성능 및 대용량 파일 처리

권장 목표:

- 일반 EML: 50MB 이하
- 첨부파일: 가능한 경우 수십 MB 수준
- 대량 첨부파일: 브라우저 메모리 상황에 따라 제한

Base64 변환 과정에서 원본 파일과 Base64 문자열이 동시에 메모리에 존재할 수 있으므로 대용량 파일 처리 시 메모리 사용량을 고려합니다.

다운로드가 완료된 후 생성한 Blob URL은 반드시 해제합니다.

```text
URL.createObjectURL()
        ↓
EML 다운로드
        ↓
URL.revokeObjectURL()
```

단일 HTML 파일이므로 외부 JavaScript/CSS 파일을 불러오는 네트워크 요청은 발생하지 않습니다.

## 12. 코드 구성

단일 HTML 파일 구조를 사용합니다.

```text
eml-generator/
└─ index.html
```

`index.html` 내부:

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <!-- meta / title / favicon -->
    <style>
        /* 전체 CSS */
    </style>
</head>
<body>

    <!-- HTML UI -->

    <script>
        // 전체 JavaScript
    </script>
</body>
</html>
```

JavaScript는 별도 파일로 분리하지 않고 `<script>` 내부에 작성합니다.

코드는 다음 기능별 영역으로 구분합니다.

```text
상태 관리
 ├─ 이메일 입력 상태
 └─ 첨부파일 목록

파일 처리
 ├─ 파일 선택
 ├─ 드래그 앤 드롭
 └─ 파일 제거

입력값 검증
 ├─ 이메일 주소 검증
 ├─ 필수값 검증
 └─ 파일명 정리

헤더 생성
 ├─ 헤더 인코딩
 ├─ 날짜 생성
 └─ Message-ID 생성

본문 생성
 ├─ text/plain
 ├─ text/html
 └─ multipart/alternative

첨부파일 생성
 ├─ ArrayBuffer 변환
 ├─ Base64 변환
 └─ attachment MIME 생성

MIME 생성
 ├─ boundary 생성
 ├─ multipart/mixed 생성
 └─ 최종 EML 생성

다운로드
 ├─ Blob 생성
 ├─ 다운로드 실행
 └─ Object URL 해제

UI
 ├─ 오류 표시
 └─ 초기화
```

외부 CDN이나 불필요한 라이브러리 사용을 최소화하고, 가능하면 순수 JavaScript로 MIME 생성 기능을 구현합니다.

### MIME 테스트

```text

텍스트 + HTML + 여러 첨부파일
```

### 인코딩 테스트

```text
한글
日本語
中文
English
😀
특수문자
```

제목, 표시 이름, 파일명, 본문에서 정상적으로 표시되는지 확인합니다.

### 브라우저 테스트

- Chrome
- Edge
- Safari
- Windows
- macOS

### 보안 테스트

- HTML 본문에 `<script>` 포함
- HTML 이벤트 핸들러 포함
- 외부 리소스 포함
- 특수문자 파일명
- 비정상적인 이메일 주소
- MIME boundary와 유사한 문자열이 본문에 포함된 경우

생성기 자체에서 HTML 본문을 실행하지 않도록 하고, 생성된 EML은 알파카 EML 뷰어의 HTML sanitization 기능을 통해 안전하게 표시되는지 함께 확인합니다.

## 14. 최종 결과물

최종적으로 **단일 HTML 파일만으로 실행 가능한 브라우저 기반 EML 생성 웹앱**을 제작합니다.

```text
┌──────────────────────────────────────┐
│ ALPACA TOOLS                         │
│                                      │
│ 알파카 EML 생성기                    │
│ 이메일을 EML 파일로 만들어보세요.    │
├──────────────────────────────────────┤
│                                      │
│ 보낸 사람                             │
│ [ alpaca@example.com              ]  │
│                                      │
│ 받는 사람                             │
│ [ user@example.com                ]  │
│                                      │
│ 제목                                 │
│ [ 테스트 이메일                    ]  │
│                                      │
│ 본문 형식                             │
│ ○ 일반 텍스트  ○ HTML               │
│                                      │
│ 본문                                 │
│ ┌──────────────────────────────────┐ │
│ │ EML 테스트를 위한 이메일입니다.  │ │
│ └──────────────────────────────────┘ │
│                                      │
│ 첨부파일                              │
│ [ 파일을 선택하거나 끌어놓으세요 ]   │
│                                      │
│ [ EML 파일 생성 ]   [ 초기화 ]       │
│                                      │
├──────────────────────────────────────┤
│ 이 도구는 이메일을 실제로 발송하지   │
│ 않습니다. EML 파일만 생성합니다.     │
└──────────────────────────────────────┘
```

최종 핵심 기능:

**① 이메일 정보 입력 → ② 본문 작성 → ③ 첨부파일 추가 → ④ MIME 구조 생성 → ⑤ `.eml` 파일 다운로드**

프로그램은 `index.html` 하나만으로 실행할 수 있으며 서버나 별도의 프로그램 설치가 필요하지 않습니다.

앞서 설계한 **알파카 EML 뷰어**와 연계하면 다음과 같은 테스트 환경을 구성할 수 있습니다.

```text
┌──────────────────────┐
│ 알파카 EML 생성기    │
│                      │
│ 이메일 작성          │
│ 첨부파일 추가        │
│          ↓           │
│       EML 생성       │
└──────────┬───────────┘
           │
           │ .eml
           ↓
┌──────────────────────┐
│ 알파카 EML 뷰어      │
│                      │
│ EML 열기             │
│ MIME 분석            │
│ 본문 표시            │
│ 첨부파일 확인        │
└──────────────────────┘
```

따라서 두 웹앱을 함께 제공하면 **EML 파일을 직접 생성하고 브라우저에서 다시 열어 검증하는 테스트 환경**을 구축할 수 있습니다.

특히 일반 텍스트 메일뿐 아니라 **HTML 메일, 한글 제목, 한글 파일명, multipart/alternative, multipart/mixed, 다양한 첨부파일**을 직접 만들어 EML 뷰어의 기능을 검증할 수 있습니다.

### 핵심 개발 원칙

> **실제 메일 발송 기능은 구현하지 않습니다. 브라우저 내부에서 표준 MIME 구조의 EML 파일을 생성하고 사용자의 PC에 다운로드하는 데 집중합니다.**

> **단일 `index.html` 파일만으로 독립 실행 가능하도록 HTML, CSS, JavaScript를 모두 하나의 파일에 포함합니다.**
