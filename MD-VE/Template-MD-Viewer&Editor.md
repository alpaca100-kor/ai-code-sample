# 웹 브라우저 기반 JavaScript 앱 제작 요청

## 1. 개발 환경

- 언어 : HTML / CSS / JavaScript
- 프레임워크 : (택 1)
  - [x] Vanilla JS (프레임워크 없음)
  - [ ] React
  - [ ] Vue
  - [ ] 기타 :
- 파일 구성 : (택 1)
  - [ ] 단일 HTML 파일 (CSS/JS 인라인 포함, 바로 열어서 실행)
  - [x] 별도 파일 (index.html + style.css + script.js)
  - [ ] 빌드 도구 사용 (Vite 등)
- 외부 라이브러리 : Markdown 파싱 및 HTML 렌더링을 위해 `marked.js` 사용. CDN 방식으로 불러오되, 가능하면 최신 안정 버전을 사용
- 지원 브라우저 : 최신 버전의 Chrome / Edge / Safari 우선 지원. 최신 브라우저의 표준 기능을 활용하며 구버전 브라우저는 지원하지 않음
- 인터넷 연결 필요 여부 : 기본적으로 오프라인에서도 사용할 수 있도록 설계. 외부 라이브러리는 CDN 의존성을 줄일 수 있도록 필요하면 로컬 파일로 포함할 수 있는 구조 고려

## 2. 프로그램 목적

마크다운(`.md`) 문서를 웹 브라우저에서 불러와 내용을 확인하고 편집할 수 있는 웹앱을 제작합니다.

웹앱은 기본적으로 좌우 분할 화면으로 구성합니다. 왼쪽 영역에는 마크다운 문서를 HTML 형태로 변환하여 서식이 적용된 상태로 보여주는 Viewer를 배치하고, 오른쪽 영역에는 원본 마크다운 문서를 플레인 텍스트 형태로 보여주는 Editor를 배치합니다.

사용자가 오른쪽 Editor에서 마크다운 문서를 수정하면 별도의 저장이나 새로고침 없이 변경된 내용이 왼쪽 Viewer에 실시간으로 반영되어야 합니다.

편집이 완료된 문서는 `.md` 파일로 다운로드할 수 있어야 합니다. 또한 가능하다면 사용자가 처음 불러온 기존 파일을 수정한 후 동일한 파일에 바로 저장할 수 있는 기능을 구현합니다.

## 3. 주요 기능

필수 기능

① **마크다운 파일 불러오기**
- `.md` 파일을 파일 선택창을 통해 불러올 수 있어야 합니다.
- 파일을 불러오면 오른쪽 Editor에 원본 마크다운 텍스트를 표시합니다.
- 왼쪽 Viewer에는 마크다운 서식이 적용된 결과를 표시합니다.
- 현재 열려 있는 파일명을 화면에 표시합니다.

② **마크다운 Viewer**
- Markdown 문법을 HTML로 변환하여 서식이 적용된 상태로 표시합니다.
- 제목, 문단, 강조, 기울임, 취소선, 목록, 링크, 인용문, 코드 블록, 인라인 코드, 수평선, 표 등의 일반적인 Markdown 문법을 지원합니다.
- Viewer는 편집할 수 없는 읽기 전용 영역으로 구성합니다.
- 긴 문서는 Viewer 영역에서 독립적으로 스크롤할 수 있도록 합니다.

③ **마크다운 Editor**
- 오른쪽 영역에 마크다운 원문을 플레인 텍스트로 표시합니다.
- 사용자가 자유롭게 내용을 수정할 수 있어야 합니다.
- 여러 줄 입력 및 일반적인 텍스트 편집 기능을 지원합니다.
- Editor에서 입력한 내용은 실시간으로 Viewer에 반영합니다.
- 입력 시 불필요한 지연이 발생하지 않도록 적절한 이벤트 처리 및 렌더링 방식을 사용합니다.

④ **실시간 미리보기**
- Editor의 내용이 변경될 때마다 Viewer를 자동으로 다시 렌더링합니다.
- 별도의 '미리보기' 버튼을 누르지 않아도 변경 사항이 즉시 반영되어야 합니다.
- Markdown 문법 오류가 발생하더라도 웹앱 전체가 중단되지 않도록 예외 처리를 적용합니다.

⑤ **문서 저장 및 다운로드**
- 현재 Editor의 내용을 `.md` 파일로 다운로드할 수 있어야 합니다.
- 기존 파일을 불러온 경우 원본 파일명을 최대한 유지하여 저장합니다.
- 새 문서인 경우 기본 파일명을 적절하게 지정합니다.
- 저장할 때 UTF-8 인코딩을 사용하여 한글이 깨지지 않도록 합니다.

⑥ **기존 파일에 바로 저장**
- 가능하다면 브라우저의 File System Access API를 활용하여 사용자가 처음 불러온 파일에 변경된 내용을 직접 저장할 수 있도록 구현합니다.
- 지원 브라우저에서는 '저장' 버튼을 이용하여 기존 파일을 직접 덮어쓸 수 있도록 합니다.
- 브라우저가 File System Access API를 지원하지 않는 경우에는 기존 방식의 `.md` 파일 다운로드 방식으로 자동 대체합니다.
- 사용자의 파일을 서버로 업로드하지 않고 브라우저 내부에서 처리하는 것을 기본으로 합니다.

선택 기능 (있으면 작성, 없으면 생략)

① **새 문서**
- 현재 문서를 초기화하고 새로운 빈 Markdown 문서를 작성할 수 있는 기능을 제공합니다.
- 저장되지 않은 변경사항이 있을 경우 문서를 초기화하기 전에 사용자에게 확인합니다.

② **문서 저장 상태 표시**
- 현재 문서가 저장된 상태인지 수정된 상태인지 화면에 표시합니다.
- 예: `저장됨`, `수정됨`
- 저장되지 않은 변경사항이 있는 상태에서 페이지를 닫거나 새로고침하려는 경우 가능하면 사용자에게 경고합니다.

③ **화면 비율 조절**
- Viewer와 Editor 사이의 구분선을 마우스로 드래그하여 좌우 영역의 크기를 조절할 수 있도록 합니다.

④ **Editor 단축키**
- `Ctrl + S` / `Cmd + S` : 저장
- `Ctrl + O` / `Cmd + O` : 파일 열기
- `Ctrl + N` / `Cmd + N` : 새 문서
- `Tab` 등 기본적인 텍스트 편집 동작이 가능하도록 구성합니다.

## 4. 사용자 작업 순서

1. 웹앱을 실행합니다.
2. '열기' 버튼을 클릭하여 마크다운(`.md`) 파일을 불러옵니다.
3. 왼쪽 Viewer에서 마크다운 서식이 적용된 문서를 확인합니다.
4. 오른쪽 Editor에서 마크다운 원문을 수정합니다.
5. Editor의 변경 내용이 왼쪽 Viewer에 실시간으로 반영되는 것을 확인합니다.
6. 편집이 완료되면 '저장' 버튼을 클릭하여 기존 파일에 저장하거나, 브라우저가 해당 기능을 지원하지 않는 경우 `.md` 파일로 다운로드합니다.

## 5. 화면 구성 (레이아웃)

상단

- 앱 제목 또는 로고
- `새 문서` 버튼
- `열기` 버튼
- `저장` 버튼
- `다른 이름으로 저장` 버튼
- 현재 파일명
- 저장 상태 표시

중앙

- 화면 전체를 좌우 2개의 영역으로 분할합니다.
- 왼쪽 : **Markdown Viewer**
  - 마크다운 서식이 적용된 HTML 문서를 표시
  - 읽기 전용
  - 독립적인 세로 스크롤 지원
- 오른쪽 : **Markdown Editor**
  - 원본 Markdown 텍스트를 편집할 수 있는 텍스트 영역
  - 독립적인 세로 스크롤 지원
  - 긴 문서를 편집할 수 있도록 충분한 편집 공간 제공
- Viewer와 Editor 사이에는 구분선을 배치합니다.
- 가능하다면 구분선을 드래그하여 Viewer와 Editor의 너비를 조절할 수 있도록 합니다.

하단

- 현재 문서의 상태 표시
- 문자 수 또는 파일 크기 등 간단한 문서 정보를 표시할 수 있도록 구성합니다.

반응형 대응

- 모바일 대응 필요 여부 : 필요
- 화면 크기별 레이아웃 변화 :
  - 데스크톱 및 태블릿에서는 Viewer와 Editor를 좌우 2분할로 표시합니다.
  - 좁은 화면에서는 Viewer와 Editor를 상하 구조로 변경할 수 있도록 합니다.
  - 모바일에서도 문서 열기, 편집, 저장 기능을 사용할 수 있도록 구성합니다.
  - 단, 데스크톱 환경을 주요 사용 환경으로 간주하여 UI를 설계합니다.

## 7. 데이터 저장 및 상태 관리

- 데이터 저장 필요 여부 : 필요
- 저장 방식 (택 1) :
  - [x] 브라우저 저장 (File System Access API 및 Blob 다운로드 방식)
  - [ ] 서버/백엔드 연동 (API 명세 별도 작성 필요)
  - [ ] 저장 없음 (세션 중에만 유지)
- 새로고침 시 데이터 유지 필요 여부 : 기본적으로 불필요. 다만 저장되지 않은 문서가 있는 경우 페이지를 이탈하려 할 때 경고를 표시합니다.
- 여러 기기/브라우저 간 동기화 필요 여부 : 불필요
- 서버 업로드 없이 사용자의 로컬 PC에서 파일을 읽고 편집하고 저장하는 로컬 중심 구조로 구현합니다.
- File System Access API 지원 여부를 확인하여 기존 파일 직접 저장 기능과 다운로드 기능을 적절하게 분기합니다.

## 8. 디자인 및 스타일

- 디자인 톤 : 미니멀하고 깔끔한 문서 편집기 스타일
- 다크/라이트 모드 지원 여부 : 가능하면 지원
- 참고할 만한 디자인/서비스가 있다면 : VS Code, Typora, Obsidian 등의 Markdown 편집 환경을 참고하되 특정 서비스의 UI를 그대로 복제하지 않습니다.
- 폰트/아이콘 사용 여부 :
  - 시스템 기본 UI 폰트를 우선 사용합니다.
  - 버튼에는 직관적인 아이콘을 사용할 수 있습니다.
  - 외부 아이콘 라이브러리는 반드시 필요한 경우에만 사용합니다.
- Viewer는 일반적인 문서 읽기에 적합한 타이포그래피를 적용합니다.
- Editor는 고정폭 글꼴을 사용하여 Markdown 문법과 들여쓰기를 쉽게 확인할 수 있도록 합니다.
- Viewer와 Editor의 구분이 명확하도록 적절한 배경색과 테두리를 사용합니다.
- 과도한 애니메이션이나 장식 요소는 사용하지 않습니다.

## 9. 예외 처리 및 오류 대응

- 입력값이 잘못된 경우
  - Markdown 파일이 아닌 파일을 선택했을 경우 사용자에게 안내합니다.
  - 파일 형식이 `.md`가 아니더라도 텍스트 파일로 읽을 수 있는 경우에는 사용자가 열기를 진행할 수 있도록 할지 고려합니다.
- 네트워크 오류 (API 연동 시)
  - 기본적으로 서버 및 API를 사용하지 않으므로 네트워크 오류에 대한 처리는 필요하지 않습니다.
  - CDN에서 외부 라이브러리를 불러오는 경우 라이브러리 로드 실패에 대한 예외 처리를 적용합니다.
- 데이터가 없을 경우 (빈 상태 화면)
  - 문서를 아직 열지 않은 상태에서는 Viewer에 사용 방법 또는 빈 상태 안내를 표시합니다.
  - 빈 Markdown 문서를 새로 생성한 경우에는 빈 Viewer를 표시합니다.
- 파일 읽기 오류
  - 파일을 읽을 수 없는 경우 사용자에게 오류 메시지를 표시하고 기존 문서 내용은 유지합니다.
- 파일 저장 오류
  - 사용자가 저장 권한을 거부하거나 저장 과정에서 오류가 발생한 경우 오류 내용을 사용자에게 안내합니다.
  - 저장 실패 시 편집 중인 Markdown 내용이 사라지지 않도록 합니다.
- 오류 메시지 표시 방식 : 화면 내 메시지를 기본으로 사용하며, 개발 및 디버깅 목적의 상세 오류는 콘솔 로그에 기록합니다.

## 10. 성능 요구사항

- 대용량 데이터 처리 필요 여부 : 일반적인 Markdown 문서 기준으로 수 MB 수준의 파일을 원활하게 처리할 수 있도록 설계합니다.
- 목록이 많을 경우 가상 스크롤 등 최적화 필요 여부 : 일반적인 Markdown 문서에서는 불필요합니다.
- 이미지/파일 업로드 시 용량 제한 : 별도의 서버 업로드가 없으므로 서버 측 업로드 제한은 없습니다.
- Editor 입력 시 매번 전체 DOM을 불필요하게 재구성하지 않도록 주의합니다.
- 필요하면 입력 이벤트에 짧은 debounce를 적용하여 대용량 Markdown 문서에서도 Viewer 렌더링 성능을 확보합니다.

## 13. 테스트

- 테스트 방법 :
  - Chrome / Edge / Safari 최신 버전에서 브라우저 수동 확인
  - 데스크톱 및 모바일 화면 크기 확인
  - 실제 `.md` 파일을 불러와 Viewer와 Editor의 동기화 여부 확인
  - 파일 저장 및 다운로드 결과를 다시 열어 내용 확인
  - File System Access API 지원 브라우저와 미지원 브라우저에서 각각 확인
- 최소 확인해야 할 시나리오 :
  1. 웹앱을 정상적으로 실행할 수 있는지 확인
  2. Markdown 파일을 정상적으로 열 수 있는지 확인
  3. 한글 Markdown 문서가 깨지지 않는지 확인
  4. 제목, 목록, 링크, 코드, 표 등의 Markdown 문법이 정상적으로 렌더링되는지 확인
  5. Editor 수정 내용이 Viewer에 실시간으로 반영되는지 확인
  6. 문서 수정 후 저장할 수 있는지 확인
  7. 다른 이름으로 저장할 수 있는지 확인
  8. 기존 파일 직접 저장 기능이 정상적으로 작동하는지 확인
  9. 저장하지 않은 상태에서 새 문서를 만들거나 페이지를 이탈할 때 경고가 표시되는지 확인
  10. 저장 실패 또는 파일 읽기 실패 시 편집 내용이 유지되는지 확인
  11. `Ctrl + S`, `Ctrl + O`, `Ctrl + N` 및 macOS의 `Cmd` 단축키가 정상적으로 작동하는지 확인
  12. 모바일 또는 좁은 화면에서 UI가 정상적으로 표시되는지 확인

## 14. 결과물

- 실행 가능한 HTML/CSS/JS 코드
  - `index.html`
  - `style.css`
  - `script.js`
- 사용된 외부 라이브러리 목록 및 선택 이유
  - `marked.js` : Markdown 문서를 HTML로 변환하기 위한 Markdown 파서
  - 필요할 경우 `DOMPurify` : Markdown 렌더링 결과의 HTML을 안전하게 정제하기 위한 라이브러리
- 앱 사용법
  1. 웹앱을 실행합니다.
  2. `열기` 버튼으로 Markdown 파일을 불러옵니다.
  3. 왼쪽 Viewer에서 렌더링 결과를 확인합니다.
  4. 오른쪽 Editor에서 Markdown 원문을 수정합니다.
  5. 수정 내용이 왼쪽 Viewer에 실시간으로 반영되는지 확인합니다.
  6. `저장`을 눌러 기존 파일에 저장하거나, 브라우저가 지원하지 않는 경우 Markdown 파일을 다운로드합니다.
  7. `다른 이름으로 저장`을 사용하면 새로운 파일로 저장할 수 있습니다.
